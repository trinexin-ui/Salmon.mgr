# Правила проекта

Единый источник правил проекта. Соблюдать всегда, в любом инструменте.
Claude Code читает `CLAUDE.md` (ссылается сюда), Codex — этот файл. Текст один.
Появится ещё один инструмент — добавить ему ссылку на этот файл.

## Правила

1. Где что лежит: `docs/DESIGN.md` — токены-основа; `docs/ui-kit.md` — чек-лист компонентов; `src/shared/ui` с папками `atoms`, `molecules`, `organisms`, `vendor`.
2. Цвета, отступы, радиусы, размеры и стили текста берутся только из `docs/DESIGN.md`. Хексов, значений в квадратных скобках и произвольных размеров шрифта в коде нет. Цвет, которого нет в DESIGN.md, использовать нельзя, даже если его предлагает библиотека или он «просто серый». Цвет берётся ролью, роль ссылается на примитив, хекс стоит только в объявлении примитива. Текст набирается классом стиля целиком. Новых примитивов, ролей и стилей текста без команды владельца не заводить.
3. Прототип десктопный: одна ширина 1440. Брейкпоинтов, префиксов вида `md:` и медиазапросов в проекте нет.
4. Всё видимое на экране собирается из `src/shared/ui` — кнопка, ссылка, поле, меню, карточка, иконка, стиль заголовка и любое другое видимое. В страницах остаётся только раскладка: сетка, порядок блоков, отступы токенами. Своей кнопки, своей ссылки со стилями и одноразовой карточки прямо на странице быть не может.
5. Нужного элемента нет в UI Kit — порядок такой: определить уровень, дописать пункт в `docs/ui-kit.md`, собрать компонент в нужной папке, сверить с макетом, отметить галочкой и только потом ставить на экран. Обойти этот порядок нельзя даже ради одной маленькой кнопки.
6. Уровни и импорты: атом ничего не импортирует из `shared/ui`; молекула — только атомы; организм — молекулы и атомы; страница — организмы и молекулы. Обратно и через голову нельзя. Файлы shadcn лежат в `vendor`, уровнем не считаются и наружу из компонентов не торчат.
7. Иконки только из макета владельца, с теми же именами.
8. Без команды владельца не делать: git, публикацию, установку новых UI-библиотек, замену шрифта, «улучшение» цветов и отступов на свой вкус.
9. Перед словом «готово» пройти этот список и вслух сказать, что из него нарушено.

## Прототип (flow) — `src/features/prototype`

Кликабельные флоу живут здесь. Оболочка уже собрана и **переиспользуется, а не рисуется заново** под каждый флоу:

- **`PhoneShell`** — мокап устройства (титановая рамка `bg-gradient-white_gray`, чёрный безель, Dynamic Island, боковые кнопки), фон `project/black_bg`, по центру экран 402×874. Оборачивает каждый флоу через `Outlet` роутера; между экранами не перемонтируется (анимируется и скроллится только содержимое). Новый флоу не пересобирает мокап.
- **`status_bar` (организм)** — готов и финален: вектор владельца (`Status Bar.svg`, `currentColor`), прозрачный, закреплён сверху, всегда виден при скролле. **Статус-бар НЕ срисовывать с макета заново и не хардкодить его цвет под экран.** Цвет (ink) **динамический**: белый над тёмным содержимым, `#000000` над светлым — вычисляется по тому, что находится под баром (`elementFromPoint` в `PhoneShell`). Чтобы тёмная зона под баром делала ink белым — пометь её атрибутом `data-sb-dark`.
- **Неактивные элементы**: всё, что не завязано на сценарий, показывает подсказку «этого нет в сценарии» и обычный курсор. Указатель (pointer) только у контролов с `data-ui-path`. Навигацию по пути вешать через `PathLink`.
- **Переходы** между экранами мягкие, скроллбары скрыты (`prototype.css`). Данные — инлайн-заглушки в коде.
- **Экраны переиспользуются между флоу — не пересобирать.** Готовые экраны лежат в `src/features/prototype/screens` (сейчас: `HomeScreen`, `EmployeeCardScreen`, `TrainingScreen`, `SuccessScreen`). Разные флоу часто стартуют с одного и того же `Home` — его НЕ делать заново.
- **Новый флоу = только своя точка входа + свои новые экраны.** На уже существующем экране добавляется лишь новый переход: неактивный элемент «оживляется» обёрткой `PathLink` на новый маршрут. Пример: flow_2 (period_goal) стартует с готового `Home` — нужно лишь повесить переход на карточку **bank-goal** (сейчас она статична/неактивна) к новому экрану «Period plan». Несколько активных точек входа на одном экране — это нормально (остальное по-прежнему показывает подсказку «этого нет в сценарии»).
- **Новый флоу (чек-лист)**: новые экраны в `src/features/prototype/screens`, маршруты в `App`, путь описать в `docs/flow.md`. Оболочку (`PhoneShell` + `status_bar`) и существующие экраны переиспользовать.
