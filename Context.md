# Context — Salmon Manager App

Живой документ. Здесь собирается контекст проекта, стек, инструменты, пайплайны задач и план. Любое изменение процесса или решения фиксируется здесь (см. [Rules.md](Rules.md)). Роли агентов — в [Agents.md](Agents.md).

## 1. Продукт

Мобильное приложение для **менеджеров розничных магазинов** в реферальной программе банка Salmon (Филиппины).

**Как работает программа.** Сотрудники магазина предлагают покупателям кредитные продукты банка и получают бонус за одобренные кредиты.

**Проблема.** Многие магазины используют один общий реферальный номер на всю команду. Менеджер не видит вклад каждого, раздаёт бонусы «на глаз» и не знает, как мотивировать людей.

**Решение.** Приложение для менеджера: видеть команду, честно делить бонусы, мотивировать людей, расти самому.

**Скоуп.** Только приложение менеджера. Приложение сотрудника — отдельный продукт, в скоуп не входит.

**Валюта и локаль.** Филиппинское песо `₱`, язык интерфейса — английский (как в макетах).

## 2. Денежные правила (неизменяемые)

- ₱100 за каждый одобренный кредит.
- Дополнительные ₱500 за каждую пятую заявку.
- Личный заработок сотрудника **неприкасаем**: менеджер не может его уменьшить или перераспределить.
- Пул банк-бонуса менеджер распределяет на командные цели (Team goal).
- Любая денежная логика живёт в одном месте — `src/domain/money` — как чистые функции с юнит-тестами. В компонентах деньги не считаются.

**Открытый вопрос:** «каждая пятая заявка» — каждая пятая _одобренная_ или каждая пятая _поданная_? Уточнить у владельца продукта до реализации, до этого в коде считать «пятая одобренная» и пометить `TODO(question)`.

## 3. Ключевые сценарии менеджера

1. **Видеть команду** — главный экран-дашборд.
2. **Честно делить бонусы** — командные цели и распределение пула.
3. **Мотивировать людей** — признания, челленджи, whisper, Shoutouts, обучение.
4. **Расти самому** — уровень, лига магазина, Possibilities.

## 5. Технический стек

**Формат поставки:** обычное **веб-приложение (SPA), открываемое в WebView через браузер**. Не нативное приложение, никаких мобильных фреймворков (React Native, Flutter, Capacitor, Expo и т. п.).

> **Прототип — десктопный, фиксированная ширина 1440 (решение владельца, 2026-10-04).** Дизайн-систему и экраны верстаем под 1440 без брейкпоинтов, без `md:`/медиазапросов, без запаса под касание. Ранняя «мобильная 375px / safe-area / touch 44px» рамка на этот прототип не распространяется (оставлена ниже как история; вернёмся к ней, если появится мобильная сборка). Dev-сервер и preview на порту **3000**, страница витрины — `/style-guide`.

| Область                   | Выбор                                                                                                                                                         |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Сборка                    | Vite                                                                                                                                                          |
| Язык                      | TypeScript (strict)                                                                                                                                           |
| UI                        | React                                                                                                                                                         |
| Роутинг                   | React Router                                                                                                                                                  |
| Стили                     | Tailwind CSS v4 (CSS-first, `@theme static`) + CSS-переменные для дизайн-токенов                                                                              |
| Шрифт                     | Geist (Google Fonts), веса 400/500                                                                                                                            |
| Оверлеи (a11y)            | shadcn/ui в `src/shared/ui/vendor` — только для открывающегося (modal, select, dropdown, tooltip, toast), вид и имя мои; ставится при первом таком компоненте |
| Юнит и компонентные тесты | Vitest + Testing Library                                                                                                                                      |
| E2E                       | Playwright, десктоп-viewport 1440×900                                                                                                                         |
| Качество                  | ESLint, Prettier, `tsc --noEmit`                                                                                                                              |
| Данные на старте          | Моки в `src/data` за интерфейсом репозиториев; реальный API подключается позже без переписывания UI                                                           |
| Backend                   | Не в скоупе на старте. Решение принять, когда появятся требования к API                                                                                       |

**WebView-специфика, которую учитываем с первого дня:**

- viewport-meta и `env(safe-area-inset-*)` для вырезов и home-индикатора;
- `100dvh` вместо `100vh`; блокируем резиновую прокрутку страницы там, где нужно;
- touch-цели не меньше 44×44 px; никаких hover-only взаимодействий;
- без зависимостей от браузерных API, недоступных в WebView (проверять перед использованием);
- сборка — статика, должна работать по обычному HTTPS-адресу тестового стенда.

## 6. Структура репозитория (целевая)

```
Salmon/
├── Context.md  Rules.md  Agents.md
├── index.html
├── package.json
├── docs/             DESIGN.md (основа), ui-kit.md (список компонентов)
├── src/
│   ├── app/          маршруты, провайдеры, layout
│   ├── index.css     дизайн-токены (примитивы/роли/типографика) → Tailwind
│   ├── style-guide/  витрина /style-guide
│   ├── shared/ui/    дизайн-система: atoms, molecules, organisms, icons, vendor (shadcn)
│   ├── domain/       чистая бизнес-логика (деньги, лиги, уровни) + тесты
│   ├── data/         моки и репозитории
│   ├── features/     home, team, employee, goals, shoutouts, profile
│   └── test/         setup для тестов
├── e2e/              Playwright
└── public/
```

Импорты в `shared/ui` только снизу вверх: atom не тянет ничего из shared/ui; molecule — только atoms; organism — molecules и atoms. `vendor` (shadcn) уровнем не считается, можно использовать на любом уровне.

## 9. Пайплайн задачи (стандартный)

1. **Оркестратор** формулирует задачу: цель, макеты, критерии готовности. Фиксирует в разделе «Активные задачи» ниже.
2. **Implementer** реализует; перед экраном сверяется с Figma.
3. **QA** пишет и запускает тесты, проверяет в мобильном viewport.
4. **Code Reviewer** проверяет diff.
5. Замечания возвращаются Implementer; цикл до зелёных проверок.
6. **Оркестратор** коммитит, пушит, закрывает задачу краткой записью в журнале и отчитывается владельцу одним коротким сообщением.

Если пайплайн конкретной задачи отличается от стандартного, отличие записывается сюда.

> Иконки — **фундаментальный набор** в `src/shared/ui/icons` (как `vendor`): импортируются с любого уровня, включая атомы, т.к. вшиты внутрь компонентов. Компонент `Icon` (`name`/`size`/`className`), глифы — `currentColor`.

**Дизайн-система из Figma (десктоп 1440).** Пайплайн этой задачи (отличается от стандартного — сборка покомпонентно со сверкой скриншотов):

1. Основа: переменные Figma → `docs/DESIGN.md` → токены в `src/index.css` → Tailwind. ✓
2. Список компонентов по уровням из макета → `docs/ui-kit.md`. ✓
3. Экспорт иконок (SVG) из Figma в `src/shared/ui/icons`.
4. Сборка снизу вверх, по одному компоненту: сначала точные значения из Figma → файл → скриншот результата → сверка с макетом. Расхождение → стоп и вопрос владельцу.
5. Варианты Figma (свойство=значение) → пропсы с теми же именами; `свойство?` → boolean.
6. Витрина `/style-guide` пополняется по мере сборки; оверлеи работают по-настоящему.

Правила уровня: токены вместо хексов/px; текст — классом стиля; импорты только снизу вверх; переиспользование вместо копипасты; курсор-указатель на кликабельном.
